# 重复模拟验证任务：效率与结果可靠性验证方案

**版本：** 1.2<br>
**日期：** 2026-09-08<br>
**状态：** 软件自动化价值的受控验证已完成；人工基线与量化效率对照经所有者决定延期，不阻塞后续开发<br>
**关联：** UC-008 / SW-VAL-001–003 / TD-048<br>
**主要目标：** 用可复查证据说明工程任务收益，不以商业付费或公开发布为前提

## 1. 验证的问题

一个工程师需要反复检查模拟信号调理电路不同版本的数据，计算 DC 增益、偏置、
线性与残差，检查异常记录，对照验收条件，整理结果并与上次运行比较。
AVS 的假设价值是减少重复操作、转录和报告整理，保持一致的计算与判断。

本方案验证完整任务，不以按钮数量、功能数量、100% statement coverage 或
解析吞吐量代替用户收益。已有工程成果继续保留，不为了对照实验重写分析核心
或放宽证据规则。人工量化对照是增强证据的可选研究，不是继续产品开发的前置条件。

## 2. 当前能力与待验证边界

| 环节 | 已有能力 | 本任务要检查的成本或缺口 |
|---|---|---|
| 输入 | 严格 csv-replay.v1、显式通道/单位/质量 | 普通表格转换及核对成本；不声称任意仪器 CSV 即插即用 |
| 分析 | DC 拟合、质量处理、准则与结果导出 | 用独立参考检查数值与结论，而非仅比较 AVS 自己生成的 golden |
| 重复运行 | 本地项目、预设、顺序批次、取消与部分结果 | 复用配置、换输入、指定新目录的实际操作 |
| 报告 | 从 finalized result 生成 text/Markdown/HTML/SVG | 普通批次不会自动发布整套人类报告，另行生成所需时间必须计入 |
| 交接 | 项目快照、分析结果引用、artifact 哈希与历史比较 | 原始输入副本须在案例包中明确保留；运行快照不等于原文件归档 |

首轮使用 Simulator 和新建临时 CSV_REPLAY 数据与输出目录。没有现场数据时，
可以证明受控任务的操作效率与软件正确性，但不能声称已验证真实仪器文件兼容、
生产环境收益或测量精度。若以后使用获授权的历史文件，应另行记录来源与映射；
当前执行标签仍为 CSV_REPLAY，不因此升级为 BENCH。

## 3. 首轮任务与案例包

限定为低压 DC 分析，暂不混入迟滞、频响、实时串口、原始流持久化或框架迁移。
准备一份同格式的普通输入/输出表格集合，模拟相同信号链的重复验证任务。
字段、单位、有效性和排除规则必须在任务说明中明确，不能要求任何一方猜测。

案例包准备阶段至少包含：

| 案例 | 目的 | 参考要求 |
|---|---|---|
| A：名义线性数据 | 检查正常分析与报告 | 由简单确定公式构造，独立算出增益、偏置和残差 |
| B：参数漂移 | 检查超限判断 | 只改变已说明的参数，明确应触发的验收条件 |
| C：带饱和/缺失记录 | 检查数据处理 | 冻结哪些点可排除、剩余点能否支撑结论；不把“含异常”自动等同 FAIL |
| D：有效证据不足 | 防止错误 PASS | 预期不足状态/原因明确，不把执行成功当成工程合格 |
| E：非法单位或文件结构 | 检查入口拒绝与恢复 | 预期在解析或验证阶段拒绝，不能伪造分析数值 |

案例数、实际数值、阈值、容差和预期结论在制作案例包时冻结并由独立参考核对。
独立参考可用手算和透明的表格公式，不调用 AVS 分析、evaluator 或报告实现。
禁止把 AVS 的实际输出直接复制成唯一正确答案。

两条路径使用相同的普通原始输入。AVS 如需转换成 csv-replay.v1，转换、补齐
可确认元数据、映射复核和脚本准备全部计入成本；不能编造未知采样时间、
实物来源或质量判断。原始表格与转换后文件都保留，转换说明单独保存。

共同交付物：每份输入的分析或明确拒绝/不足原因、采用的准则与点处理、
必要图表、可读结果说明，以及两次有效运行的变化比较和证据来源。
人工报告无需模仿 AVS 的 JSON/manifest 内部格式，只需满足相同信息清单。
不得让人工多做无关工作，也不得免除 AVS 的额外整理步骤。

## 4. 公平对照方法

基线允许操作者熟悉的 Excel 模板或既有 Python 脚本，不要求手算全部数据。
记录基线版本、已有模板和经验；若后来改进基线或 AVS，两者的准备工作都单独记账。
同一比较中不得把基线“首次学习”与 AVS“熟练复用”混为一组。

执行分三步：

1. **软件预演：** agent 可准备案例和参考，使用现有 CLI/Replay/报告路径验证可执行性。
   记录机器耗时与操作清单；此步不是人工效率测量。
2. **实际操作：** 操作者先熟悉两条路径，再按同一交付要求各自完成任务。
   分开记录首次环境/模板准备和熟悉后的重复任务；首轮建议至少三组配对重复，
   交替执行顺序，使用难度相当的数据变体，记录学习效应和所有协助。
3. **复核与最小改进：** 按共同清单核查交付物。仅修复记录到的阻塞或重复劳动，
   以新版本复测；保留改动前数据，不以重试成功覆盖失败。

至少一名真实操作者即可形成初步自测证据；若操作者是项目作者，明确标为作者自测，
不推断陌生用户表现。不得用 agent 自动点击、估算人类速度或预设人工错误替代实测。
如果没有实际操作者，人工部分保持 NOT_RUN；软件案例准备仍可独立推进。

计时从取得同一输入包开始，到全部交付物可按清单复核为止。首次安装、环境配置、
数据转换、配置、运行等待、报告整理、问题恢复和复核分别记录。
人工介入时间与端到端时间分列；不把机器执行时间全部称为节省的人工时间。
失败、求助、重试与超时也进入记录；未完成的任务不能被当作更快完成。

## 5. 指标与判断

| 指标 | 记录与解释 |
|---|---|
| 首次成本 | 安装、学习、模板/脚本与映射准备时间；已有资产注明，不虚构历史成本 |
| 端到端时间 | 达到相同交付标准的总耗时，包含必要等待与恢复 |
| 人工介入 | 实际操作及复核时间，不以执行步骤数推算 |
| 数值/结论正确性 | 与独立参考及预先冻结容差核对；记录每项差异 |
| 异常识别 | 已知异常检出数/异常总数，正常误报数/正常总数；无对应样本时为 N/A |
| 操作错误 | 实际误选配置、漏步、转录错误的原始次数和预先定义的检查机会数 |
| 交付完整性 | 原始输入、转换、配置/准则、处理理由、结果、比较能否被定位和复核 |
| 重复性 | 语义结果是否一致；区分合理变化的时间/运行 ID 与工程指标变化 |

人工操作错误与注入数据异常分开统计。通过全部故障样本不能表述为“人工错误率
下降”。数值计算一致不能表述为仪器更准确；校准系数也不是计量证书。

分别报告每次数据、样本数、配对时间差及中位数/范围，不只展示最快一次。
某项节省比例为 (基线时间 - AVS 时间) / 基线时间；基线为零时记 N/A。
不预设“提升 50%”等成功数字，也不从少量作者自测推断普遍收益。

解释复用收益时，可报告 T(n) = 首次成本 + n × 重复任务时间。
明确该表达式是基于当前样本的估计；只有重复成本确实更低时才讨论抵消首次
成本所需次数，不能把推算当成已执行的多次任务。

## 6. 阶段出口

- SW-VAL-001：同任务、独立参考、阈值容差、格式映射和软件交付清单已冻结并通过 HOST_TEST；
- SW-VAL-002：人工量化对照保持 DEFERRED；如果未来恢复，仍须完整记录准备、操作、等待、失败与协助；
- SW-VAL-003：软件自动化链的结果与交付已经复核，结论明确适用场景和未验证范围。

完成评估与证明收益分开判断：结果可以是观察到收益、未观察到收益或因阻塞无法
比较。存在错误 PASS 或参考不一致时，不得用更短时间宣布整体成功；
应定位问题、修复并保留复测证据。

只有真实记录支持时，才能在展示中写“在某任务、某基线、某环境和某样本中节省了
多少时间”。当前可写“已将数据校验、拟合、验收判断、报告、历史和差异比较整合为
可重复的自动化流程，并用独立参考验证受控案例”；不得增加未经测量的效率百分比。
SYNTHETIC、CSV_REPLAY、HOST_TEST、SPICE_IDEAL、BENCH_CONTROLLER 和 BENCH
继续区分；本阶段无硬件操作，也不产生新硬件验证结论。
