# ADR-0001：软件优先并采用 Ports and Adapters 边界

**Status:** Accepted  
**Date:** 2026-08-29

## Context

项目原始路线以模拟前端硬件为核心，并计划由 MSP430 或其他控制器完成采集。当前用户希望先交付成熟、独立的软件产品，硬件采购和搭建后置。同时，软件必须保持与 MSP430、未来 AFE、其他 3.3 V 控制器和潜在仪器的兼容性。

如果分析代码直接依赖某个串口、开发板 SDK 或 GUI，软件会再次成为特定硬件的附属品。

## Decision

采用软件优先的 Ports and Adapters 架构：

- 领域核心包含测量模型、质量规则、分析和判定；
- 应用层编排连接、测试运行和报告；
- `DeviceAdapter` 是设备端口；
- Simulator、CSV Replay、Serial、MSP430 和未来仪器是适配器；
- UI/CLI 通过应用服务工作，不直接访问设备或重新实现算法；
- Software v1 的完成不依赖真实硬件；
- 未来硬件通过适配器接入，不修改领域算法。

Software Phase 1 使用 `src/analog_validation/` 作为正式包根目录。当前 `dashboard/` 中可复用算法迁移后不保留第二份核心实现。

## Consequences

正面影响：

- 无硬件也可以测试和发布；
- 更换开发板不需要重写分析；
- 适配器可通过统一契约测试；
- MSP430 兼容性与产品核心保持分离。

代价：

- 前期需要先设计领域模型和接口；
- 某些简单脚本会被拆成多个明确模块；
- 串口和 GUI 功能不会在最初阶段立即增加。

## Alternatives considered

1. **继续以 MSP430 为主控：** 拒绝，因为会把独立产品绑定到另一项目。
2. **先完成 GUI 再整理核心：** 拒绝，因为会造成分析和设备逻辑散落在界面代码中。
3. **为每块板建立独立应用：** 拒绝，因为测试和报告无法复用。
